## 4. モデル・プラットフォーム方針

WebLLM＋WebGPUは計画上の第一候補に留める。Transformers.js＋ONNX Runtime Webは比較候補である。どちらも本プロジェクトへの正式採用、品質、速度、容量、モバイル成立性を保証しない。

評価時は特定AIプラットフォームに依存しないアダプターを使い、同一の固定データ・プロンプト・出力スキーマ検査で比較する。モデル名だけで採用せず、取得元・版・量子化・Tokenizer・ランタイム・ライセンス・設定を固定する。遠隔推論や有料APIへ暗黙にフォールバックしない。

## 5. 安全・プライバシーの成立条件

公開前に少なくとも次を実通信・実ブラウザで検査する必要がある。

- 会話本文、名前、ファイル名、ハッシュ、分析結果が外部送信されないこと。
- モデル取得通信と会話データ処理を分離し、取得先・容量・ライセンスを表示すること。
- 入力本文を命令として実行せず、プロンプトインジェクションによる合意捏造・反対根拠削除・未確認の確認済み化を検出すること。
- HTML、URL、SVG、JSON、DOCX/PDFを未信頼データとして扱い、外部参照・コード実行・XSS・過大展開を防ぐこと。
- GitHub Pages等の同一オリジンにある他アプリとの保存境界を検証すること。フォルダ分離だけではR25を満たさない。
- IndexedDBの消去・容量不足・共有端末閲覧のリスクを説明し、保存失敗を成功表示しないこと。

**現時点の判定:** これらは設計要件としては明記されているが、実装・実通信による証拠がないため安全ゲート成立とはいえない。
