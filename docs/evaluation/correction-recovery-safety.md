# 訂正・回復安全性の追加回帰

## 同じ発言へのUndo後に下書きが古くなる

Inspectorは選択IDが変わった場合だけフォームを同期していた。同じ発言を訂正してUndoすると、表示上の原文や分類は戻っても、分類selectや原文textareaには訂正後の値が残る。別項目の保存によって、取り消した内容を再適用するおそれがある。

修正前に分類と原文の実UI回帰がそれぞれ失敗することを確認した。選択発言の確定値（分類・話者・重要指定・原文・復帰先・所属議題・復帰線の相手）が変わった場合にだけ下書きを同期する。プロジェクト全体のobject identityや保存通知への依存は増やさず、無関係な保存で編集中の下書きを消さない。

`e2e/inspector-draft-sync.spec.ts`は分類訂正→Undoでのselect同期、原文訂正→Undoのtextarea同期、無関係な保存中の下書き保持を確かめる。

## 入力中Escapeによる下書き消失

従来のwindow共通ハンドラーは入力欄からのEscapeも詳細を閉じていた。入力・原文textarea・IME/消費済みイベントの実UI回帰3件で修正前の失敗を確認した。

入力欄・textarea・select・contenteditable、IME変換中、既に処理済みのEscapeでは共通の閉じる処理を行わない。編集欄の外にフォーカスがある場合は従来どおりEscapeで閉じ、最新の選択ノードへフォーカスを戻す。明示的な閉じるボタンも維持する。

`e2e/escape-editing.spec.ts`は下書きとフォーカスの保持、編集欄外からのEscapeでのノード復帰、合成IMEイベントとpreventDefault済みイベントを検証する。合成イベントの成功を実IMEや実機の受入完了とは扱わない。従来の`focus.spec.ts`と`undo-escape-regression.spec.ts`も維持する。

## G5とは分けて扱う

これらは確認済みの訂正・回復不具合を防ぐ局所的な回帰であり、全回復・全キーボード導線・実支援技術の受入完了ではない。G5全体、共有ホスト負荷・OSキャッシュ統制、実機・実GPU・heap・実AI品質は未完了のままとする。旧SHAのテスト成功や性能値を、新しい公開SHAのfresh検証として引き継がない。
