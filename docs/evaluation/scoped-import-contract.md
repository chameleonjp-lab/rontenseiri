# 限定JSONの復元契約

限定JSONは、選択発言だけを復元するためのデータであり、完全バックアップではない。未知キーを捨てるだけでは、既知の`source.text`末尾や議題の`arrival`に対象外の情報を追加した入力を防げなかった。これらは単体テストで旧実装の受理を再現してから修正した。

## 受け入れるもの

アプリが生成した限定出力の固定契約を満たすものだけを復元する。選択されたutterance IDとmanifestのID・順序が一致し、議題は一つ、履歴・解析runを含まず、範囲は`excerpt`である必要がある。

原文は選択発言のquoteを元の時系列順に改行で連結した内容と完全一致する。限定sourceのID・version・name・hash・warningsは生成時の固定形式でなければならない。議題全体の到達点・次の行動・未決事項・成立状態は限定出力の固定値だけを認める。manifestが完全バックアップ・履歴付き・原文網羅・整理完了を主張した場合も拒否する。

## 拒否と正規化

既知フィールドに範囲外の原文や議題全体の結論が含まれる場合は、内容を黙って書き換えず拒否する。矛盾するmanifestも拒否する。未知の独自キーは従来どおり明示DTOに含めず、復元後へ引き継がない。正規の限定export/import、複数sourceにまたがる非連続選択、話者仮名化は回帰試験で維持する。

これは入力の内部整合性・範囲限定を守る契約で、JSON作成者や原文の真正性を認証する署名ではない。第三者がquote自体を偽造したかは、署名なしJSONだけでは判定できない。また話者仮名化はspeaker属性の置換であり、quote中に含まれる名前の匿名化保証ではない。

回帰試験は`tests/scoped-import-boundary.test.ts`。完全バックアップの高度な推論・系譜・Undo情報を失わせる修正ではなく、`scope:agenda`に限って適用する。
