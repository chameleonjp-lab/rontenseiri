# 問い改版の旧版応答・要再確認・保存復元を確かめる限定試験

## 今回確認すること

統合要件v0.4の[R15](../requirements-and-development-plan.md#r15-訂正の影響がある結論を更新するか要再確認にする)は、問いなどの訂正で影響する結果を再計算するか要再確認にし、無関係な結果を保ち、取消後も状態が整合することを求める。今回は問いの条件変更に限定した通常UIの経路を追加する。製品コードは変更しない。

`e2e/r15-question-revision-reload-undo.spec.ts` は、原文の問いU01、旧版への回答U02、無関係な発言U03を含む完全JSON fixtureを通常の復元UIから取り込む。議題Rのまとめ依存はU02だけで、問いU01は含めない。問い版から旧版応答を辿らず、問いの原文だけを直接失効させる実装では合格しない。無関係な議題BはU03だけに依存し、関係エッジは置かない。初期状態は両議題とも確認済みで、旧版への回答は要求充足を記録してある。

1. 「この端末に保存」で最初のIndexedDB保存版を作る。
2. 「問い・根拠」の「版を変更」で「費用は？」を「税込の費用は？」へ改版し、理由を入力する。ここからは明示保存せず、実際の自動保存を待つ。
3. 読み取り専用のIndexedDB観測で、旧版の`superseded`、新版の`active`・`supersedesId`・現行参照、旧版を指す回答オブジェクト全体の不変、Rだけの`needsReview=true`を検査する。原文版・発言・関係と到達点も変わらないことを確認する。
4. `page.reload()`でReactとモジュール状態を破棄し、「最近の作業」から保存版を再開する。振り返りにはRだけの要再確認警告があり、元の到達点は残る。問いUIでは旧版と現行版を区別し、回答表示が旧版IDとU02を指したままであることを確認する。
5. 全体JSONプレビューを保存内容と深く比較する。通常の「訂正履歴」から1回Undoし、自動保存後に議題・reasoning graph・原文・発言・関係が初期状態へ戻ることを確認する。共有履歴は改版記録を保持し、Undoがその正しいIDを指す。
6. もう一度リロードして最近の作業から再開する。R/Bとも警告がなく、旧版が再び現行で、回答は同じ版を指す。完全JSONはUndo後DB内容と一致し、追加Undoは無効であることを確認する。

## 再読込後のプレビュー同期契約

議題R→B→Rの画面確認も自動保存を起こすため、2回の再読込後の`preview`には対象project IDと共有履歴件数（改版後1、Undo後2）を渡す。既存の読み取り専用IndexedDB観測でそのIDの選択議題Rと期待履歴件数を最大10秒pollし、さらに「現在版は保存済み」表示を待ってから出力ダイアログを開く。初回の未保存プレビューはoptional引数を省略し、保存を要求しない。

全体30秒、poll 10秒、完全payload比較・scope/manifest検査は維持する。固定sleep、retry、プレビュー再クリックや製品変更は加えない。保存完了とプレビュー失効が競合する旧ヘルパーの同期不足への限定対策であり、過去すべての失敗の原因確定、製品不具合やデータ損失、全不安定性の解消は主張しない。

## 証拠の読み方

初期保存版、改版後保存版、改版後リロードの完全JSON、Undo後保存版、Undo後リロードの完全JSONの5点を、PlaywrightのJSON attachmentに残す。通常復元UIの後、ブラウザ内のテスト評価はnative IndexedDBの読み取りだけに使う。domain/storage関数の直接実行、状態注入、保存成功stubは使わない。fixtureのgraph作成はNode側のテスト準備であり、問い・回答の作成UIを検査した証拠ではない。

保存と出力の比較では、ナビゲーションの`selectedAgendaId`と保存メタデータの`saved`・`storageRevision`・`updatedAt`だけを除く。保存済み表示・savedフラグ・保存世代増加は別に検査する。改版の共有履歴とreasoning側イベントの参照も検査する。Undoではreasoning graph全体を初期値と比較するため、改版イベントはそのgraphから戻るが、共有履歴の改版＋Undoは残る。

完全SHAと実行結果の対応はDraft PR本文で示す。変更前・失敗した実行のログは別ディレクトリに保持し、最終SHAの成功へ読み替えない。直前#31で報告された「4 passed表示後にプロセスが終了しなかった」既存実行は本試験の成功証拠ではなく、独立の未解消な実行プロセス上の問題として残す。この追加試験のコマンドも、個別assertion結果とコマンド終了コードの両方で評価する。

## 今回は確認しないこと

- #24の訂正UI全般、#31の原文への否定追加、#26–#30のdomain依存グラフ・反復・分岐は再実装しない。既存`question-summary-persistence.spec.ts`のdomain/storage直接実行とは別に、改版とUndo・自動保存・再開を通常UIでつなぐ。
- 1問い・1旧版応答・1依存まとめ・1無関係まとめ・1改版・1Undoだけを対象とする。撤回、問い分割、回答付替え、複数段依存、混合解釈候補、再解析、lineageは含まない。
- fixtureの問いと応答は事前に用意する。空の作業からの問い・回答作成UI、実モデル、意味判断の品質は対象外。外部AIは使わない。
- JSONは完全出力プレビューを調べる。ファイルのダウンロード、改版後ファイルの再インポートは含まない。
- 保存失敗・競合・別タブ・強制終了・保存途中のリロード・容量・性能・ピークメモリは対象外。
- 開発用headless Chromiumのdesktop viewportに限定する。production/offline、スマートフォン、実OS、支援技術、キーボードだけの一連操作の受入ではない。

R15全体、G5全体、G0–G8の受入完了は宣言しない。先行Draftは計画上の積み上げ基点であり、実際のマージを意味しない。
