# R15：部分Undo後に新しい訂正を加える

[繰返し訂正と3段Undo](r15-repeated-correction-undo.md) の次の小さな検証。未マージDraft #29 head `0a136983ea394a2a28d99a02844c9ec8a78d5650` を計画上の積上げ基点とし、製品コードは変えず、同じfixtureを使う追加2ケースと本文書だけを差分にする。#29のマージを前提に計画は進めるが、実際のマージは主張しない。

## 確認する状態

Aの原文訂正→Bの話者訂正→Aの再訂正を行い、2回UndoしてAの最初の訂正だけが残る状態へ戻す。この時点でBの要再確認は消えるが、Aと共有まとめは要再確認のまま。そこからBに新しい原文訂正／話者訂正を追加する2ケースを検査する。

完全JSON復元後の次のUndoは、放棄した旧訂正ではなく新規B訂正を戻す。その次はAの最初の訂正を戻し、元の意味状態とUndo枯渇へ到達する。旧B話者や放棄したAの再訂正は復活してはならない。各段階でJSON出入力を挟み、元の3訂正、新規訂正、4つのUndoの合計8履歴を保持する。Undo target IDの順序は旧A再訂正→旧B訂正→新規B訂正→最初のA訂正に固定する。

## 期待値と限界

[テスト](../../tests/r15-repeated-correction-undo.test.ts) は前スライスの独立した直接比較helperを再利用し、製品snapshotや依存探索を期待値に使わない。新規訂正直後の全議題と全発言、関係、推論、引用と版参照を比較する。各Undoでは元の中間意味状態を直接比較し、監査prefixと原文catalog（coverageを除く）の保持を検査する。入力不変、各JSONでのsource全体と監査履歴、Undo枯渇時の拒否も検査する。

Redoの実装や履歴を削除する分岐モデルを要求する試験ではない。これは追記専用の監査履歴にUndo済み訂正を残したまま、新規訂正を正しく選択して戻せることの局所検査。単一共有TXT・8発言・domain APIの2固定ケースであり、全履歴形状、UI、IndexedDB/reload、問い分割／回答付替え、Worker／モデル、history cap、runs／metadataの全Undo復元、性能、意味品質は未検証。
