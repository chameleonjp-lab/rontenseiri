# R15 回答発言差替えの直接依存検出補強

サポのDraft #34独立静的レビューで、製品不具合ではなくテスト検出上の盲点が見つかった。旧回答U02を参照する根拠が差替え後の応答に残るため、変更IDから新回答U03が欠落しても、U02→根拠→応答→U03と伝播して新側まとめBの警告が立ち、既存ケースが通り得る。

## 分けて残す2つの証拠

`e2e/r15-response-utterance-swap-reload-undo.spec.ts`の元の非空根拠保持ケースは削除しない。根拠・問い版・応答の全フィールド保持と通常UIの保存・再開・Undo経路を確かめる証拠として残すが、新U03の変更ID欠落を単独で検出できるとは扱わない。

追加した「直接依存（根拠迂回なし）」ケースでは、根拠レコードと応答の根拠IDを空にする。関係エッジ・主張・解釈・立場変化・不確実性伝播も空、問い版の参照はU01だけ、反論先も空であることを復元後にassertする。まとめAは旧U02だけ、Bは新U03だけ、Cは独立U04だけに明示依存し、議題所属の重複もない。新しい問い依存や暗黙の伝播経路は加えない。

このgraphでは、差替え後の応答がU03だけを参照するため、U02からU03への根拠迂回経路がなく、逆向きにU03からU02へ戻る経路もない。AとB両方の警告を直接比較することで、新旧それぞれの変更IDを失った場合の見逃しを防ぐ。Cは全フィールド保持を比較する。

復元後の操作は通常UIのU02解除→U03選択→理由付き保存、自動保存、native readonly IndexedDB、再読込、完全JSONプレビュー、通常UI Undo、自動保存、2回目再読込である。元の30秒のテスト上限、10秒poll、警告・共有履歴before/after・推論履歴参照・Undo targetのassertionは弱めない。fixtureの生成以外にdomain/storage書込みAPIやstate注入を使わない。

## 限界と証拠の区別

#34確定head `4624a9de9b5541bf327de646482175af23af26b5`から独立したtest/docs-only追補とし、応答解除スライスは混ぜない。元の#33・#34に残る別箇所のJSONプレビューtimeout、無効fixtureや起動前失敗は上書きも取消しもしない。新ケースの成功は、それらの原因確定や製品修正を意味しない。

直接依存の検出力確認のために一時的な製品コード変更を使う場合も、隔離した検証用worktreeだけで行い、新旧いずれかの変更IDを故意に欠落させた結果を別証拠として保存する。その変更は開発ブランチにコミットもpushもしない。通常の正しい製品コードでの検証とmutation検証の結果は区別する。

複数応答・非空反論先・複雑な根拠graph・混合/多段依存・多段Undo・意味品質・性能の全受入は対象外。R15/G5/G0–G8全受入、既知の500-node性能問題の解消、CI成功、artifact内部照合、独立レビュー完了、実マージをこの記録だけで主張しない。
