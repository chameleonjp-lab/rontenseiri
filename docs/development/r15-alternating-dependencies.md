# R15：関係と推論を交互に通る依存

[要件 v0.4 のR15](../requirements-and-development-plan.md#r15-訂正の影響がある結論を更新するか要再確認にする) に対するドメイン回帰テスト4ケース。製品コードは変更しない。#26の単一種類の2-hop関係とは別の、関係と推論の固定点の接続を検査する。

## 今回確かめること

[テスト](../../tests/r15-alternating-dependencies.test.ts) は製品parserと `createProject` から8発言を生成し、有効な関係・推論graphを設定して `validateProject` を通す。依存は U01 → 関係 → U02（問い）→ 推論応答 → U03 → 関係 → U04（問い）→ 推論応答 → U05。最終要約はU06だけを所属本文とし、明示要約根拠U05だけに依存する。

原文の否定追加と分類変更を、関係・問い・応答配列の順序を正順／逆順にした場合のそれぞれで実行する。外側の関係走査と内側の推論走査が一回ずつだけでは、後半の依存へ届かない構成である。期待する全議題の要再確認フラグは製品の到達計算を使わないリテラルで記述する。

無関係なU07には `dependency: false` とdependency未指定の関係を置き、要再確認が広がらないことを確認する。既に要再確認のU08も保持する。全議題の完全比較では、本文、到達点、未回答、次の確認に加え、既定値ではない境界・決定・回答・合意・外部確認の各状態がフラグ変更以外は保持されることを検査する。全関係・全推論graph、入力プロジェクト非破壊性も比較する。

完全JSON出力を再インポートした後の意味スナップショット、原文catalog、監査履歴を確認し、再インポート結果で一回のUndoを行う。Undoは元の意味状態を戻す一方、原文旧版・訂正版catalogと監査履歴を消さない。

## 基点と証拠

固定基点はmain `8281db0936c7323287b6490cc71593482f0101d9`。#26のマージを待たず、別名のテストと本文書だけを追加する。#26の差分を本ブランチへ取り込まず、同PRとの同時適用に備えてファイル名を分離している。merge/rebase/force-push、Draft解除は行わない。

開発試行は公開headの証拠ではない。正確なコミット後のローカルtest/format/buildとCI取得時点はDraft PR本文に分離する。CI workflowはPRのheadをcheckoutするので、将来のmainと合成した状態を検証したとは主張しない。

## 残る確認

ドメインの明示依存だけの試験であり、意味理解の正しさ、新規AI解析、モデル、Worker、IndexedDB保存、画面・図・Markdown/SVG出力、実機性能の新しい証拠ではない。問い分割、応答付替え、evidence起点、分岐・循環、複数根拠、繰返し訂正、多段Undo/Redoも本スライスでは対象外。JSONの意味比較は製品 `semanticSnapshot` を共有するため、すべてのmetadata/runsを独立検査したとはしない。R15/G5、G0–G8全体は未受入のまま。

#24 head `ef3e4708f4d479fae036c85f7546cb60dbd1e7a0` のローカル500-node選択/検索p95 = 232.1/217.7ms（200ms上限超過）は、そのSHAと環境固有のR20/G5失敗として保持する。このスライスやCIの成功で取り消さず、基準も変更しない。
