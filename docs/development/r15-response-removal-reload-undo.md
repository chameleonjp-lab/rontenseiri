# R15 応答解除の自動保存・再読込・Undo

通常UIで応答の関連だけを1回解除し、その解除状態を自動保存・再読込してからUndoする限定回帰である。先行の「応答編集→解除→Undo→明示保存」やdomain/storage API経由の保存証拠とは分ける。製品コードの変更や全受入の証拠ではない。

## 通常UIで確かめる経路

`e2e/r15-response-removal-reload-undo.spec.ts`は、問いU01、回答U02、独立U03と、既存の1問い版・1応答・非空根拠を完全JSONの通常復元UIから取り込む。まとめAはU02だけ、BはU03だけに明示依存する。発言の議題所属は重複させず、問い依存や関係エッジによる伝播経路は置かない。非空根拠は問いU01だけを参照し、旧回答U02を参照する根拠から応答への迂回経路を置かない。初回だけ明示保存し、通常UIの応答編集フォームで理由を記入して「理由を記録して応答の関連を解除」を選ぶ。解除より前に応答を編集・保存しない。

応答カードとgraph上の応答がなくなる一方、Aだけが要再確認となり、Bは全フィールドを保持する。Aの回答状態・到達点・次の一手等も要再確認フラグ以外を保持し、未回答へ自動変更しない。「未回答・反論なしとは断定しません」という解除直後の表示も確認する。問い・問い版・非空根拠とその他graph、原文・全発言・関係を直接比較する。

共有履歴が1件の`reasoning:response-removed`となり、beforeには元の応答を含むgraph、afterには応答のないgraphとAの警告状態が保存されることを検査する。推論履歴の`response-removed`が同じ共有履歴IDをbefore/afterで参照し、理由とtargetも一致することを照合する。

明示保存を追加せず、実際の自動保存とnative IndexedDBのreadonly transactionから保存状態・世代増加を観測する。再読込→最近の作業から再開→応答カード不在・Aのみ警告・到達点保持→完全JSONプレビューを比較する。その後、通常の訂正履歴から1回Undoし、自動保存と2回目の再読込後に元の応答・全議題・推論graph・原文・発言・関係と警告解除を確認する。元の共有履歴prefixを保ち、Undo targetが解除履歴IDを指し、余分なUndoができないことも確認する。

## 証拠の読み方と限界

fixture作成だけはdomain APIを使う。復元後の操作・保存・再開・Undoは通常UIのみで、ブラウザevaluateはnative IndexedDBのreadonly観測に限定する。アプリstate注入やdomain/storage API経由の変更はしない。全体比較では選択議題・保存フラグ・保存世代・更新時刻のみを除き、保存状態と世代の増加は別途検査する。完全JSONはプレビュー解析であり、download/reimportの検証ではない。

再読込後、議題をAへ戻してプレビューを生成する前に、readonly DBの選択議題・履歴件数と画面の「現在版は保存済み」を待つ。後続のproject更新によってクリアされる古いプレビューを待ち続ける方法は採らない。既存の全体30秒・poll上限10秒は延長せず、内容比較も弱めない。実行ごとのSHA・未コミット状態・テストファイルhash・終了コード・生ログ・JSON観測と失敗traceは別フォルダへ保存する。

先行Draft #33の最終JSONプレビューtimeoutと、#34の関連ブラウザ実行に含まれる未変更#33ケースの最初のreload後JSONプレビューtimeoutは、別箇所の失敗証拠として保持する。今回のケースが通っても、その失敗の取消しや原因確定とは扱わない。公開CI結果、artifact内部照合、独立レビュー、実マージの各状態も区別する。

対象は1応答解除・U02への単独依存・独立まとめ・1Undoのみ。同一問い内のsuperseded版移動、複数応答、非空反論先、混合/多段依存、多段Undo、保存失敗・競合、意味品質、全viewport、実モデル、外部AI、性能は未検証。R15/G5/G0–G8全受入や既知の500-node性能失敗の解消は主張しない。Draft #34を計画上の基点にするが実マージ済みとは報告せず、merge/ready/rebase/force-pushを行わない。

サポによる#34の独立静的レビューは、旧U02参照の根拠から新U03へ伝播できるため新U03の変更ID欠落を検出できない可能性を指摘した。製品不具合ではなくテスト検出上の盲点である。今回の解除ケースでは根拠参照をU01へ分離したが、新旧回答双方の失効証拠とは呼ばない。#34の既存非空根拠保持ケースを残し、その検出補強は#34確定headを基点に別のtest/docs-only追補とする。変更前fixtureの初回通過証拠も上書きしない。

最初の確定head実行は関連5件中3 pass / 2 fail、exit 1。新ケースは根拠注記に含めたU02までcheckboxの部分一致が拾うstrict-mode違反で解除前に失敗し、製品不具合ではない。発言checkboxを先頭ID `^U02\b` で特定するよう限定し、チェック済みassertionは維持する。もう1件は未変更の問い改版ケースで、最初のreload後のJSONプレビュー待機が全体30秒でtimeoutした。両方とも別証拠として残し、先行#33・#34の失敗と混同しない。
