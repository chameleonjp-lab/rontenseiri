# R12：手動の排他解釈 A/B — 限定実装と検証

## できること

「問い・根拠」で対象の問い版を明示選択し、解釈 A/B の前提・結論・原文に結びついた根拠を利用者が入力します。2候補と排他グループは1回の操作で反映されます。AIによる生成結果ではなく、両方とも「手動で登録した未確定候補」です。比較対象を開く、強調する、原文を表示する操作は、どちらかの採用・確認になりません。

各候補の結論に依存する既存の意味項目は、名前とIDを確認して明示選択します。前提→候補の結論→指定した依存結論の未解決の伝播を保存します。候補の編集時は変更した側の旧・新依存先だけを再確認対象にし、無関係な候補・項目・依存リンクは変更しません。議題のまとめについては、影響先の発言IDを `summaryDependencies` に明示登録した議題だけ `needsReview` を付けます。曖昧な類似度による再関連付けは行いません。

候補を削除する操作は、参照切れを作らない「撤回」です。排他グループは2候補を保持し、撤回済みと明示します。残った候補を採用したり、依存先を確定したりしません。撤回済みの候補を修正しても自動復活しません。再撤回と変更のない更新は拒否します。

## 原子的な保存と復旧

- `saveManualInterpretationPair` は新規登録・更新とも Project のコピー上で処理し、検証後にだけ返します。不明・欠落・重複ID、根拠なし、異なる問い版への更新、確認済み指定、手動ペアでないグループへの編集は拒否します。
- 一括反映に成功したときだけ、この候補ペアの下書きを消します。別の問い・応答などの下書きは消しません。失敗したときは元Projectと候補下書きを保持します。未保存の候補編集がある状態の撤回も拒否し、別候補の下書きを黙って捨てません。
- 共通の訂正履歴に1単位として保存し、1回のUndoで候補・グループ・依存リンク・影響するまとめの直前状態を復元します。
- IndexedDB と完全JSONは、2候補、排他関係、原文参照、依存結論、撤回状態と履歴を保持します。JSONインポートは元作業を上書きせず別コピーになります。未適用フォーム下書きは永続化・JSONの対象外で、移動時に破棄確認を行います。

## 図・振り返り・出力の制限

図はこのスライスでは解釈A/Bの専用ノードを描画しません。排他候補の存在と「図だけで一方を確認済みと扱えない」ことを明示します。振り返りにも、既存の到達点・決定表示は候補の採用ではない旨を表示します。手動形式ではない既存排他グループを、手動の未確定A/Bと偽って表示・編集しません。

排他グループがあるProjectでは、**完全JSON以外の出力（限定JSON、Markdown、SVG）をエラーで停止**します。これらの形式は現状、排他関係・未確定状態を損失なく表現できないためです。関連がないように見える限定範囲も含め保守的に停止し、完全JSONを案内します。片方の枝だけを確定したように出力する代替動作はありません。

## 検証と証跡

実行コマンド、最終tested SHA、GitHub push/PR CIの実際の結論とartifactリンクは、この変更のDraft PR本文に同期します。リポジトリ内の試験は次の通りです。

- `tests/manual-interpretations.test.ts`：手動ペア生成、不正根拠による不変性、撤回とUndo。
- `tests/interpretations-boundaries.test.ts`：ID・確認指定の拒否、変更した側だけの更新、旧・新依存先、明示的なまとめ依存、JSONとUndoの厳密比較。
- `tests/export-exclusive-safety.test.ts`：完全JSONによる保持と、状態を保持できない形式のfail-closed。
- `e2e/manual-interpretations.spec.ts`：利用者入力を模した決定的なfixture、デスクトップと390px幅のブラウザ操作、原文参照、下書き、修正・撤回・Undo、IndexedDB再読込、完全JSONの別コピー復元。画面文字列だけでなく、保存された候補・項目・グループ・依存リンクを比較します。

外部AI、モデルサービス、外部への会話送信は使用しません。fixtureはテスト用の利用者入力であり、モデル品質の証拠ではありません。幅390pxのChromium試験は、iPhone実機や支援技術による検証の代替ではありません。
