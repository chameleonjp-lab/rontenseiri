# R15 同一問い内の旧版から現行版への回答付替え

同じ問いに置いたsuperseded旧版とactive現行版の間で、既存の回答の対象版だけを通常UIで変更する回帰テスト。別の問いへの付替えとは分けて検証する。製品コードは変更せず、Draft #36のhead `514bdee502ac73017bbd97bb90c3ed72ff9f5d29`を基点にしたtest/docs-onlyの追補とする。兄弟Draft #35の応答解除は含まない。

## 確かめること

完全JSONの通常復元UIから、問いU01・回答U02・独立U03を読み込む。問いは1件、版は旧版→現行版の順の2件。旧版はsuperseded、新版はactiveかつ旧版をsupersedesIdで参照し、問いのcurrentVersionIdは初めから新版を指す。回答は旧版を指す。問い・版の作成UIをテストしたという意味ではない。

まとめAの依存は回答U02のみ、独立BはU03のみ。関係エッジ・根拠・主張・解釈・立場変化・排他群・不確実性伝播・反論先を空にし、復元後もassertする。問いU01の依存や根拠経由で警告が偶然出る構成にはしない。

初回明示保存後、応答編集フォームで対象問い版だけを現行版に変更し、理由付きで保存する。問いidentity・currentVersionId・版順序・旧版superseded状態・新旧版の全フィールドは不変。応答は対象版以外のidentity・発言・種別・充足・根拠・反論先・note・actor・時点を全比較する。まとめAのneedsReviewだけをtrueにし、Bと回答あり状態を保つ。共有履歴のbefore/after全graphとまとめ、reason、共有イベントID、推論イベントIDと共有イベントへの参照・同一時刻を照合する。

自動保存完了を待ってnative readonly IndexedDBを観測し、最近の作業から再開、通常UIの版状態・応答・まとめ警告と完全JSONを照合する。次に通常UI Undo、自動保存、2回目の再開を経て、旧版を指す元の応答、元のgraph、警告解除、監査prefixとUndo targetを比較する。保存世代の増加も確かめる。fixture生成以外にdomain/storage書込みAPIやアプリstate注入は使わない。

## 実行と残る範囲

`e2e/r15-same-question-version-retarget.spec.ts`。テスト全体30秒・保存poll 10秒を維持する。出力プレビュー生成前には選択議題A・履歴件数のDB反映と「現在版は保存済み」を待つ。前スライスのプレビューtimeoutや他の失敗ログを上書き・取り消ししない。

このfixtureは1応答のみで、無関係な追加応答が保持されることは未検証。複数応答・非空反論先・複雑な根拠graph・混合/多段依存・多段Undo・保存失敗/競合・意味品質・性能・実機の全受入は対象外。R15/G5/G0–G8全受入、既知の500-node性能問題の解消、CI成功、artifact内部照合、独立レビュー取得、実マージをこのテストの成功だけで主張しない。外部AIを使わず、製品は端末内の既存経路のみで動く。
