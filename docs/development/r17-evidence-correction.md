# R17: 登録済みの根拠の発言参照と注記を訂正する

## 今回できるようにすること

[正式計画R17・R15](../requirements-and-development-plan.md#193-訂正保存出力)の次の限定機能として、登録したEvidenceの発言参照と注記を通常の「問い・根拠」画面で訂正する。根拠の選択を誤ったときに、同じ根拠IDを使う主張・回答関係を作り直さず修正できるようにする。AIを起動せず、端末内で操作できる。

中央の[要件ステータス表](../evaluation/requirements-status.md)は過去のmain snapshotであり、本機能やDraft #58の受入を示していない。R17全体の分割・統合・任意関係編集や、R15の精密意味依存、G0–G8の合格を宣言しない。

## 独立した機能差分

基点は #57 の確定head `522916d6b5b29009ff5ca67a4c2e7fac710a4c5a`、base branchは `test/r15-manual-response-link-invalidation`。#58の意味項目編集とは別の独立した操作であり、#58の変更を取り込まない。#58のCI・レビュー・マージを待たず、根拠編集のコード・単体・通常UI・保存復元・Undoを一つのfeature Draftにまとめる。テスト順序の組合せごとにPRを分けない。

着手直後、サポ・カメカメの#58旧headへのP2指摘を受けて本機能を一時停止した。#58内で交互依存連鎖を再現・修正し、修正head `f3dacdf86bd861552b272b1b8d73f15fb7ab597c` の全単体433件・関連ブラウザ47件・format/build成功、通常push・本文更新・再レビュー依頼を行ってから本機能へ戻った。本機能の変更・証拠はその修正とは別に保つ。

事前のno-cacheリモート確認時、mainは `b0de54d1510832189cc7840749cfc66b50bdc4e6`。stack内のマージとmainへの統合は区別する。この機能差分ではmain、外部でマージ済みのPR、#58を変更せず、merge・Ready化・rebase・force-pushを行わない。共通の画面と固定点処理へ独立した機能差分があるため、将来の統合時には#58との通常の競合解消・両機能の再検証が必要になる可能性がある。現在は統合済みとは扱わない。

## 編集と保持の契約

既存の根拠カードから編集し、発言を明示選択し、注記と訂正理由を入力する。編集時は全発言から選択でき、新規登録の議題scopeは維持する。取消・フォーカス移動・下書き離脱ガードと、失敗時の入力保持をそろえる。

`updateEvidence` は編集可能な `utteranceIds` と `note` のみを受け付ける。`sourceIds` は選択した発言の出典から導出し、ID・actor・確度・対象時点・登録時点を保持する。実行時に余分なフィールドを渡されても採用しない。注記の修正は、本人認証や外部資料の検証済み化を意味しない。原文と他の根拠そのものは変更しない。

発言なし、存在しない参照、重複参照、不正な注記型、空白だけの理由は拒否し、失敗した入力Projectを変更しない。根拠の削除・分割・統合、確度や時点の編集、外部資料の取得・AI解析は対象外。

## 依存先と履歴

同じ根拠IDを保つため、主張や応答が持つ既存参照は維持する。旧・新の発言と明示的な根拠依存を起点として、影響する振り返りを要再確認にする。注記だけの修正でも依存先を確認対象とし、結論を自動で新しく書かない。無関係な成分は保持する。発言を共有する意味項目がある場合、再確認範囲は保守的に広くなり得る。

根拠訂正のモードは外側の発言固定点の各反復へ維持する。根拠→意味項目→発言関係→別の意味項目→その項目への反論という交互連鎖と、立場変化の `triggerEvidenceIds` だけからbefore/after項目へ至る依存を扱う。根拠起点の反論・立場変化の追跡は今回の明示訂正で起動し、従来の原文・問い・応答の編集動作を一括変更しない。

`reasoning:evidence-updated` を共有Undoの1単位として記録する。変更前後の意味状態はProject履歴に保持し、推論監査イベントはrevision IDを参照する。Undoは根拠と要再確認状態を戻し、変更履歴は消さない。

## 検証と証拠

単体で、編集フィールド・出典導出・既存関係と出所の保持・旧新と下流の再確認・独立成分不変・不正入力・共有Undo・完全JSON往復・限定出力の非漏洩をまとめて検査する。通常UIはdesktopとmobile viewportで、明示訂正、保存、最近の作業から再開、図／振り返り／完全JSON、Undo後の再保存・再開を検査する。確認済みの基準状態は正規の確認コマンド／操作で作る。

テストの失敗・途中経過を保持し、期待値やtimeoutを弱めない。最終headをcommitしてから、clean worktreeで全単体・関連ブラウザ回帰・format・buildを実行し、SHAと生ログ・終了コード・JSON結果を証跡ディレクトリへ残す。ローカル結果、CI状態、exact-head静的レビュー、Draft公開、main統合を別々に報告する。

外部AI・外部APIキー・外部サービス・追加依存パッケージは使わない。実機のiPhone Safari、意味品質、性能や全保存競合の受入をviewportテストで代替しない。
