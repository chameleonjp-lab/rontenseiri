# R15：繰返し訂正・完全JSON復元・多段Undo

[要件 v0.4 のR15](../requirements-and-development-plan.md#r15-訂正の影響がある結論を更新するか要再確認にする) の「訂正を取り消した場合も状態が整合する」に対するテストと本文書だけのスライス。製品コードは変更しない。計画上の積上げ基点は未マージのDraft #27 head `84c85cefbe32803c6253e1c17a08bf4eafdcf97f`（その公開main基点は `8281db0936c7323287b6490cc71593482f0101d9`）。#27が実際にマージ済みとは主張しない。

## 今回確認すること

二つの独立した起点A/Bと共有まとめを持つ有効な時系列のfixtureを使う。Aは関係→問い→回答、Bは関係→結論を明示的に参照する。共有まとめは回答とBの結論を参照するが、その所属本文は依存経路に含めない。依存を無効にした線の先は再確認にせず、既存の要再確認は保持する。

1. Aを訂正し、A側と共有まとめだけを要再確認にする。
2. Bを訂正し、B側も要再確認にする。
3. Aをもう一度訂正し、それまでの両側の状態を保持する。
4. 各訂正後の完全JSON出力／インポートで意味フィールド・source全体・監査履歴を厳密比較する。
5. 3回の通常Undoで、第2訂正直後→第1訂正直後→元の状態へ戻る。途中でB側のflagだけが消え、共有まとめはAの訂正が残る間は要再確認を維持する。

「原文A→話者B→原文A」と「話者A→原文B→話者A」の2系列に、Undo間で完全JSON復元を挟む／挟まないを組み合わせた4ケース。再訂正は元の値への復帰ではなく別の値とし、同じ内容になったことをUndo成功の代用にしない。

## 独立した期待値

[回帰テスト](../../tests/r15-repeated-correction-undo.test.ts) は製品の `semanticSnapshot` や依存探索関数を期待値に使わない。各段階の `needsReview` は固定の配列で比較し、議題の到達点・合意・未回答・次の確認・依存IDなどはflag以外の全フィールドを維持する。訂正直後の話者変更は対象以外の全発言をdeep-equal、原文変更は単一共有TXT／改行なしというfixture契約から発言順によるoffset差と新しい原文版参照を独立に期待値へ反映し、全発言をdeep-equalする。関係と推論graphも直接比較する。

Undoでは、保存しておいた各中間状態の全発言・全議題・関係・推論・lineage・選択議題を直接比較する。原文の旧版／訂正版のID・本文・provenanceはcatalogに残し、引用が参照する版と文字範囲に実際に一致することも全発言で検査する。Undoはactive版のcoverageを再計算するため、catalog不変比較からcoverageだけを除外する。coverage全履歴の完全一致は主張しない。

監査履歴は毎回既存prefixを厳密に保持し、Undoごとの `targetRevisionId` が3つの異なる訂正IDの逆順になることを確認する。`canUndo` の状態、3回後の枯渇、4回目の拒否時の入力不変性も検査する。各API、出力、Undoが入力を変更しないことを比較する。

## 残る限界

単一TXT、8発言、二つの固定経路でのdomain API回帰であり、#26–#28の単発訂正／1回Undoや配列逆順を繰り返すだけの試験ではない。問い分割、回答付替え、Undo後の新規編集・分岐、Redo、履歴上限、UI、図、Markdown/SVG、IndexedDB/reload、Worker／モデル、実機性能と意味品質は未検証。問い版→応答内部の単一pass退行を独立に検出するfixtureでもない。意味比較はrunsや一部のproject metadataの全Undo復元を検査しない。

R15/G5、G0–G8は未受入。#24 head `ef3e4708f4d479fae036c85f7546cb60dbd1e7a0` のローカル500-node選択／検索p95 232.1／217.7ms（200ms上限超過）は維持し、再計測も基準緩和もしない。本スライスの小規模成功でその失敗を取り消さない。ローカル実行、公開headのCI、artifact内部検証、独立静的レビューは別々の証拠として扱う。
